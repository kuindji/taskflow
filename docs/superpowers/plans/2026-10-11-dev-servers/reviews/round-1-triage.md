# Round 1 triage

- **DS-01 (blocker): confirmed.** `signal()` keeps going after EPERM, and PID 1's tree is every user process. Fix: root first, and `signal` stops at the first refusal (both platforms). Manual item 7 now exercises EPERM on a root-owned process, which has no user-owned descendants.
- **DS-02 (blocker): confirmed.** The `+1` slack is wrong for Windows' absolute start times. `etime` with `now` sampled before `ps` biases toward signalling. Fix: `ps -o lstart=` under `LC_ALL=C TZ=UTC`, parsed with `Date.UTC`. This is the spec's original query, now locale- and DST-safe. The rule is the spec's, with no slack. Checked on this Mac: `TZ=UTC LC_ALL=C ps -o lstart= -p $$` prints `Sun Oct 11 17:58:30 2026` in UTC.
- **DS-03 (major): confirmed.** `runCommand` swallows spawn errors, and a non-zero `ps` reads as "not running". Fix: spawn errors propagate. POSIX `startTime` falls back to `kill(pid, 0)` to tell "exited" from "can't tell", and throws for the latter. Process-table reads throw on a non-zero exit or an empty table. Windows `startTime` prints `missing` explicitly, and a failed `taskkill` re-checks the table.
- **DS-04 (major): confirmed.** Windows `tree` was `[pid]`, so only the parent was awaited. Fix: one `processes()` snapshot op per platform (Windows uses `Get-CimInstance Win32_Process` with creation times). Tree and survivor checks are shared. Children older than their parent are skipped, because Windows keeps stale ppids. Windows forces per PID (`taskkill /F` without `/T`), since a graceful taskkill doesn't stop console processes. Section 5 adds an explicit Windows item, recorded as unverified when no Windows machine is reachable.
- **DS-05 (major): confirmed.** `stop()` removed by id after awaiting the stopper, and a re-add keeps the id. Fix: `DevServerStore.removeIfUnchanged(server)` matches id and `registeredAt` inside one queued operation. Added a test with a deferred stop and a re-registration.
- **DS-06 (major): confirmed.** A late `ok` filtered by id only, and `slices.backends()` can't detect a recreated slice. A rejected request after a reset re-created the error. Fix: per-key attempt tokens that reset clears, a check on every completion, and removal only when `registeredAt` also matches. Added tests for a re-registration broadcast and for close-plus-reset during the stop.
- **DS-07 (major): confirmed.** `followSocket` only patches `state: "offline"` and resets nothing (`backend-store.ts:471`). Fix: the popover and the badge show only rows whose machine is `attached`. `rehandshake` → `bootstrapBackend` already refetches on reconnect. Added a component test with an offline machine.
- **DS-08 (major): confirmed for OpenCode, rejected for promptless Kimi.** OpenCode receives only `instructions: [skillPath]` and no `PROMPT_BASE` at all. Fix: `ensureInternalAgentSkillFile` also writes `taskflow-agent-prompt.md` (PROMPT_BASE), and OpenCode's `instructions` lists it before the skill. Kimi with no prompt gets no system prompt of any kind (a pre-existing limitation of Kimi's TUI-typed channel). Fixing that would change how Kimi starts for every session, so it's recorded as a known limitation in the spec amendments rather than changed here.
- **DS-09 (minor): confirmed.** TS `remove --pid 5 --pid 6` used the last value, and `list --all` sent no headers while sh does. Fix: count `--pid` like `session move`, and send `contextHeaders()` for `--all`. Tests were updated.
- **DS-10 (minor): confirmed.** `--pid abc` is a local usage error, and `getResolvedCliHelp` inlines the doc. Fix: checklist items 8 and 11 are corrected.
- **DS-11 (minor): confirmed.** The group key included a `taskId` that resolves to no task. Fix: resolve the task first and key on it only when it's found. Added a test.

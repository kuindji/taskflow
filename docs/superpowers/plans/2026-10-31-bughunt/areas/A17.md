## Rounds

### Round 1 (2026-11-01): 3 findings, 3 confirmed

- R1-1 confirmed: `AgentAccountsSection.commit` dropped every incomplete
  row from the replacement `accounts` list, saved rows included. With a
  saved account's name or home dir cleared (not yet blurred into a save),
  saving another account deleted the cleared one from settings, and
  projects or launches pointing at it failed with "Unknown account". A
  half-cleared saved row now goes out as saved; only never-saved drafts are
  left out. 85f695e4
- R1-2 confirmed: settings text and number inputs (network name, remote app
  name, agent model fields and their fallbacks, font family fallback, font
  sizes) were bound to the saved value and saved on every keystroke, so
  React put the old text back until the backend answered; over an SSH
  primary, keystrokes typed during the round trip were lost (typing "work"
  saved "k"). New `SettingInput` keeps the typed text while focused and
  shows the saved value again on blur. 85f695e4
- R1-3 confirmed: account Browse opened this machine's folder picker and
  saved its path into a remote primary's account (the data-folder picker was
  already gated). Browse is now disabled with the local-only hint when the
  primary is another machine; the Claude section now gets the backend id
  too. 85f695e4

### Round 2 (2026-11-01): 3 findings, 3 confirmed

- R2-1 confirmed: Settings > Data Folder > Change onto a folder holding
  Taskflow data, then "Use Existing", switched the backend's task store to
  the adopted dataset but the backend broadcasts no new lists, so the
  sidebar kept the old projects and tasks (editing one failed with "Task not
  found") until a reload. `updateDataDir` with `adopt` now refetches
  primary's projects and tasks, which also clears an active task that is
  gone. (Flows, schedules and notifications staying behind is A01 R1-2.)
  f37053cb
- R2-2 confirmed: with another machine as primary, General settings (whose
  network rows are that machine's) still offered this machine's access
  token, which does not open the primary. The row now shows only while
  primary is this machine.
  f37053cb
- R2-3 confirmed: a theme picked in Appearance while the dialog's
  theme-list request was in flight was undone when the list arrived (the
  request reapplied the theme active at open), leaving the display and the
  saved setting apart. `fetchThemes` now keeps a theme picked meanwhile.
  f37053cb

### Round 3 (2026-11-01): 2 findings, 2 confirmed

- R3-1 confirmed: every new `accounts` prop replaced the saved rows in
  `AgentAccountsSection` drafts outright, so a save answering a rename put
  the old home dir back into a home dir field the user was typing into while
  the save was in flight (and blur then sent nothing, since the restored
  value matched the saved one). Same for a new account edited during its
  first save. Incoming saved values now replace only fields not edited since
  the value they were last saved or sent with. 76fb6182
- R3-2 confirmed: the Claude, Codex, OpenCode, Pi, Kimi and Remote Agent
  settings panels sat in the fixed-height, `overflow-hidden` content box with
  no scrolling of their own, so with a few accounts the lower Codex/Claude
  account rows and Add account were cut off and unreachable. Those panels
  now scroll like General and Defaults. No regression test (layout; Happy DOM
  does no layout). 76fb6182

## Rounds

### Round 1 (2026-11-01): 3 findings, 2 confirmed, 1 owner

- R1-1 confirmed (medium): the trust dialog's fingerprint came from
  `ssh-keyscan`, which reads no ssh config, so a host that is a `Host` alias
  (`HostName`) or sits behind `ProxyJump` returned no key and could never be
  trusted. The key is now collected by `ssh` itself over the same route,
  accepted into a scratch known_hosts under the record's alias, with
  `PreferredAuthentications=none`.
- R1-2 owner: a saved discovered backend never follows a DHCP address change;
  its uid matches the beacon at the new address, which hides the new row, and
  every reconnect still dials the old address. Workaround: remove and re-add.
  Following the beacon would let any LAN peer repeating the uid repoint a
  saved machine, so it is a product call.
- R1-3 confirmed (low): the tunnel forwarded to `127.0.0.1` on the remote, so a
  backend pinned to `::1` with `TASKFLOW_HOST` was never reached. It forwards
  to `localhost` now (checked against real sshd for both bindings).

Commit: 197e7a57

### Round 2 (2026-11-01): 2 findings, 1 confirmed, 1 owner

- R2-1 confirmed (medium): every TUI on a machine shares
  `~/.config/taskflow/tui/backends.json`, and the registry wrote its in-memory
  list over the file, so a machine saved in one TUI was deleted by the next
  write (attach, rename, detach) from another TUI that loaded earlier. A write
  now carries over records on disk under ids this registry never held; ids it
  held and removed stay removed. Leftover edge: a record one TUI confirmed
  onto its uid while another still holds the provisional id shows as two
  entries until the next attach merges them.
- R2-2 owner: the readiness probe accepts any Taskflow backend, so when the
  remembered port of instance A is taken by another Taskflow instance B on the
  same host (random port reuse, or `TASKFLOW_DEV_PORT`), attach stops at B,
  the token is rejected, the token refresh retries the same port, and A stays
  unreachable until the machine is removed and re-added. Fixing it needs an
  identity-aware probe (the backend proving its uid or accepting the record's
  token before the candidate is accepted), which is a protocol change.

Commit: a6a41bea

### Round 3 (2026-11-01): 2 findings, 2 confirmed

- R3-1 confirmed (medium): `sendToGroup` set the multicast interface and
  called `send` in a loop, but `dgram.send` queues the datagram behind an
  async address lookup, so every copy left through the last enumerated
  interface (checked on Bun 1.4.2: both native sends ran after the last
  `setMulticastInterface`). On a machine with Wi-Fi plus a VPN or bridge,
  peers on the other interfaces never saw its announcements or probes.
  Sends now go one at a time, each waiting for the previous callback, and
  calls queue per socket. A send error now goes to the callback instead of
  the socket's `error` event, which used to shut discovery down.
- R3-2 confirmed (medium): `UserKnownHostsFile=<path>` went to ssh unquoted;
  ssh splits the value on whitespace, so with a home folder like
  `C:\Users\Jane Doe` the scan key went to `C:\Users\Jane` and "No host
  key returned" made the machine impossible to trust (and connections could
  not find the trust store). The path is now double-quoted with `\` and `"`
  escaped, and Windows paths use forward slashes. Checked against the local
  sshd with a path holding a space, a quote and a backslash.

Commit: 3c662db8

### Round 4 (2026-11-01): 3 findings, 3 confirmed

- R4-1 confirmed (low): `joinRelative` rebuilt every rooted non-drive path
  with a single `/`, so on Windows a project on `\\server\share\repo` with
  `wiki = docs/wiki` resolved its wiki to `/server/share/repo/docs/wiki` (a
  path on the current drive), and relative markdown links and images in such
  a project broke the same way. A `//server/share` prefix is now kept as the
  root, and `..` stops there.
- R4-2 confirmed (low): `joinRelative` percent-decoded the base directory as
  well as the link, so a folder literally named `release%20notes` turned into
  `release notes` and its links failed; `resolveWikiRoot` also decoded the
  user-typed `wiki` value. Only the link target is decoded now, and
  `resolveWikiRoot` passes `{ decode: false }`.
- R4-3 confirmed (low): `extractOutline` only knew ATX headings, but the
  renderer also makes setext headings (`Title` over `===`/`---`), so they were
  missing from the outline and every later duplicate got the wrong `-n` id
  (clicking `## Notes` after a `Notes`/`===` title scrolled to the title).
  Setext headings are now tracked with a small paragraph state (a list item,
  quote, or indented code before `---` stays a thematic break), checked
  against react-markdown + rehype-slug output.

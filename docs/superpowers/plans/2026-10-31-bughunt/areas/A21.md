## Rounds

### Round 1 (2026-11-01): 3 findings, 3 confirmed

- R1-1 confirmed: the TUI picked its terminal editor from the backend's
  detected list but spawns it locally, so a remote backend with Micro or
  Neovim made editing fail on a machine that only has Vi. Now only editors
  found on the TUI's own PATH qualify. Commit: b5bcb2ab.
- R1-2 confirmed: after a failed save (offline, backend error) the retry
  saved the `# --- taskflow validation errors ---` block into task notes or
  description. The block is now stripped before validate and save.
  Commit: b5bcb2ab.
- R1-3 confirmed: a subtask's git view listened for change stats under its
  own id, but the backend tracks the shared worktree under the parent's id,
  so the view never refreshed. Same bug fixed in the desktop UI's
  `changeTargetId` (TaskHeader stats, Changes/History panes). Commit: b5bcb2ab.

### Round 2 (2026-11-01): 2 findings, 2 confirmed

- R2-1 confirmed: a git status refresh kept the selected file's diff while
  its path stayed listed, so an agent's later edits to that file never
  showed until the user reselected it. The store now reloads the requested
  change on refresh and drops it when the file leaves that side.
  Commit: 4ebfe4ee.
- R2-2 confirmed: a schedule switched to an action in the desktop UI keeps
  its old prompt (backend runs the action); the TUI editor serialized both
  and its validator rejected every save. The prompt is no longer emitted
  when `actionId` is set. Commit: 4ebfe4ee.

### Round 3 (2026-11-01): 2 findings, 2 confirmed

- R3-1 confirmed: a schedule whose action later lost its Standalone switch
  could not be saved from the TUI editor (`actionId must reference a visible
  standalone action`) even for unrelated edits; the backend still runs it and
  the desktop editor keeps the saved action. The validator now accepts the
  edited schedule's own saved action. Commit: e1bdf184.
- R3-2 confirmed: a flow run that finished while its owner's first
  `FLOW_RUNS_LIST` was in flight dropped the completion event (untracked
  run) and then installed the older `running` list. Every run update of the
  owner now bumps the event revision and an in-flight load relists.
  Commit: e1bdf184.

### Round 4 (2026-11-01): 2 findings, 2 confirmed

- R4-1 confirmed: a standalone shell action run from the TUI started the
  backend's system shell and ignored Settings > Default shell (the desktop run
  menu honours it), so a Bash-only command failed under a Dash `/bin/sh`.
  `ActionRunner` now resolves the shell with the same `configuredShellPath`
  the session picker uses. Commit: 6e848416.
- R4-2 confirmed: the R1-1 fix still took candidates from the backend's
  detected editors, so a remote backend with only Nano left a TUI machine that
  has Vi with no editor. The internal editor list moved to shared
  (`INTERNAL_EDITORS`) and the TUI checks it against its own PATH.
  Commit: 6e848416. Note: a test that opens an editor through the workspace
  must stub `SettingsStore.terminalEditor`; otherwise it launches the real
  local editor, which never exits and hangs `bun test packages/tui`.

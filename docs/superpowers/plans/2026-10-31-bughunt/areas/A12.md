## Rounds

### Round 1 (2026-11-01): 3 findings, 3 confirmed

- R1-1 confirmed: unticking a machine in the Machines menu, or removing it in
  Manage backends, detached it without the dirty check the hard switch has,
  and the detach's reset disposed its editor models, unsaved edits included.
  Both now refuse while the machine has unsaved buffers and name the files.
  d1b91782
- R1-2 confirmed: after "Work as…" a remote, every refresh (opening the
  machines menu runs one) set local's `keepAttached` back to true, because main
  lists local whenever it runs and keeps no intent for it. Local showed ticked
  while offline, and clicking it detached it again, so it could never be
  re-attached beside the remote. Refresh now keeps the row's own intent. d1b91782
- R1-3 confirmed: "Return to local" on the connection overlay needed a
  failure on the remote primary, and a remote backend that stops behind a live
  SSH tunnel closes the socket without one, so the full-screen overlay left no
  way out until the remote came back. It now shows for any remote primary.
  d1b91782

### Round 2 (2026-11-01): 2 findings, 2 confirmed

- R2-1 confirmed: the backend broadcasts connectivity only when it changes,
  and the UI asked once per machine, so a remote primary whose internet came
  back while the client's socket was down (laptop asleep) stayed "offline"
  after reconnecting, with agent launches disabled until a manual recheck. It
  is now read again whenever primary is ready. 9a0c0325
- R2-2 confirmed: Settings is mounted from launch, so its remote-agent status
  read ran before primary's connection existed (always after View → Reload),
  failed silently and was never retried: a running remote agent showed as
  stopped. The hook now reads again whenever its machine is ready. 9a0c0325

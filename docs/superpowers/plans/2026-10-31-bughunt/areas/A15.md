## Rounds

### Round 1 (2026-11-01): 3 findings, 3 confirmed

- R1-1 confirmed: Close Tab (Cmd/Ctrl+W, or the Electron menu item) closed
  the active tab directly, skipping the confirmations the tab's close button
  shows: an editor or markdown tab with unsaved edits lost them, and a
  running Vim/Neovim/Nano editor session was killed. Both paths now go
  through `requestCloseTab` (`close-tab.ts`). 69c6b68e
- R1-2 confirmed: launching a flow that has inputs from the master
  workspace stored the pending input state, but the master layout returned
  before the `FlowInputDialog` was rendered, so no dialog appeared and the
  flow never started. Both layouts now render the dialog. 69c6b68e
- R1-3 confirmed: View → Markdown Input (and the Cmd/Ctrl+Shift+E fallback)
  toggled the left pane's session even when the right split pane was
  focused. It now uses the focused pane (`focusedPaneKey` in `ui-store.ts`,
  which also replaces three copies of the same helper). 69c6b68e

### Round 2 (2026-11-01): 2 findings, 2 confirmed

- R2-1 confirmed: the expanded (Monaco) editor of an `ExpandableTextarea`
  always wrote its buffer back on close. With a task's description or notes
  expanded while an agent or another client updated that field, closing the
  editor untouched overwrote the newer text with the old one, and the task
  panel autosaved it. `MonacoEditorDialog` now reports only an edited
  buffer. 0cd65d17
- R2-2 confirmed: `requestCloseTab` destroyed the terminal before the
  backend took the close. A remote tab whose machine is attached but refuses
  the close (socket down) is kept by `closeTab`, so it was left blank with
  no recovery subscription. The terminal now goes only after the close
  succeeds. 0cd65d17


### Round 3 (2026-11-01): 2 findings, 2 confirmed

- R3-1 confirmed: opening or closing the split view changed
  `SplitContainer`'s root element (`DndContext` only while open), so React
  remounted the left pane. A legacy browser tab (web UI, or a workspace on a
  remote machine) lost its page and history, back to its initial URL. The
  `DndContext` is now always rendered. 92c0a4df
- R3-2 confirmed: `useSessionSync` kept the previous machine's default shell
  while the newly selected machine's shell list was in flight, so New
  Terminal (Cmd/Ctrl+T) in that window sent e.g. `/bin/zsh` to a Linux
  backend. The resolved shell is now tied to the machine and shell setting it
  was resolved for. 92c0a4df

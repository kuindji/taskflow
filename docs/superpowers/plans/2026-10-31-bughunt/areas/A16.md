## Rounds

### Round 1 (2026-11-01): 3 findings, 3 confirmed

- R1-1 confirmed: `AgentOptionsPanel` built "off" choices as omitted fields
  (Codex bypass `false || undefined`, OpenCode auto-approve, Pi thinking
  "off" and empty tools, Kimi "manual"), and `normalizeAgentOptions` did the
  same for saved flow inline actions. The backend merges run options over the
  machine defaults, so with Codex "Bypass Safety" on in settings, turning it
  off in Run with options (or in a saved action) still launched with
  `--dangerously-bypass-approvals-and-sandbox`. Non-headless panels now send
  the explicit value. Side effect: an action saved before this opens with
  Save enabled once (same as any stored value differing from the prefill).
  5c37b0f1
- R1-2 confirmed: `ScheduleForm` offered only standalone actions and an
  effect cleared the selection otherwise, so after an action's "Standalone"
  was turned off, opening its schedule and saving any edit sent
  `actionId: null` plus the old custom prompt (the scheduler does not check
  standalone). The schedule's own action stays offered. 5c37b0f1
- R1-3 confirmed: Run now discarded the trigger's rejection (`void
  handleTrigger`), so "Schedule is disabled" (A05 R3-2) and other failures
  showed nothing. The Schedules dialog now shows a dismissible error.
  5c37b0f1

### Round 2 (2026-11-01): 2 findings, 2 confirmed

- R2-1 confirmed: `useRunMenu`'s `navigate` set the active task only when
  the row had one, so running a script, agent command or action from a
  project's Run menu while a task was open left that task's workspace on
  screen (`useActiveWorkspace` prefers the active task) and hid the new
  session. It now clears the active task for project rows. c48d1b62
- R2-2 confirmed: `OpenCodeOptions` used the fixed id `opencode-auto-approve`,
  so with two inline OpenCode actions in a flow, clicking the second one's
  "Disabled" label flipped auto-approve on the first action, which was then
  saved. The id now comes from `useId`, as in `CodexOptions`. c48d1b62

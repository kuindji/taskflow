# Round 2 triage

Each finding was checked against the code on main (9b7853c8).

1. **SESSION_CLOSE bypasses the session queue.** Confirmed, downgraded to minor. `handlers/session.ts:73-78` removes the ref outside the queue. Every interleaving still ends with the ref and log gone, because the exit cleanup is queued and reads the current owner. The only effect is a brief ghost ref in the target's broadcast. Fixed anyway, since it's cheap: `closeClientSession` runs the removal on the session queue (Section 2).
2. **Lock cycle through native discovery.** Confirmed. Archive holds the owner lock and calls `failFlowByIds` (`handlers/task.ts:153`), which takes FlowRunner's lock (`flow-runner.ts:539`). `startFlow` holds that lock while it launches (`flow-runner.ts:104`), and the launch takes the native lock, which is per agent type (`native-session-discovery.ts:148`). With the plan, discovery held that lock until its write ran on the session queue, behind a move waiting for the archive's owner lock. Fixed: the lock is released when the id is identified, through a release-once wrapper. A barrier test was added (Sections 2 and 3).
3. **Rollback is inconsistent for Master.** Master part confirmed. `task-store.ts:238-250` mutates the cache before the write, and `getMasterSessions()` serves the cache. Fixed: build the next list, write it, then assign (Section 1), plus rollback tests for both Master directions (Section 3). The failed-undo part was rejected as a design change. It takes two consecutive write failures. Boot repair covers duplicate refs, and the policy is documented in Section 3.
4. **Shutdown redirects queued output to the spawn owner.** Confirmed. `pty-manager.ts:295` flushes before `onExit`, and the plan's shutdown branch deleted the owner synchronously, ahead of the queued appends. Fixed: deregister on the session queue. A test was added (Section 3).
5. **Shutdown admits creates/resumes.** Rejected. This behaviour predates the feature and isn't move-specific. `reconcileSessionList` (`task-store.ts:264-298`) marks a same-instance live agent ref from an earlier boot interrupted, so a late ref recovers the same as one marked at shutdown. Moves are already gated.
6. **Owner locks aren't cross-process.** Rejected. A dev instance archiving or deleting a task that holds another instance's live session is already possible for every session, without moves. Each move step runs under the cross-process file locks (`task-store.ts:981`) and fails closed with "Task not found", and the move then rolls back.
7. **File links use the mounted owner.** Confirmed. `terminal-link-provider.ts:125` captures `workspaceKey`, and lines 168 and 260 route the stat and the editor through it. Fixed: `sessionWorkspace()` resolves the current tab's workspace and owner on every provide and click (Section 6).
8. **Deterministically failing and timing-based tests.** Confirmed. The nested `withOwnerLocks` reserved its second key late, so the plan's own test failed. The native-id test drained before the discovery write was queued. Fixed: atomic key reservation (Section 1), a barrier-based native test with `waitFor`, and `lockRequested` spies replacing the 10 ms sleeps (Section 3).
9. **Toolbar drops fall through to reorder.** Confirmed. The marker was on `TaskDropZone` only (`TaskSidebar.tsx:441`), so drops on the toolbars at lines 411 and 476 weren't caught. Fixed: mark `AppShell`'s `data-panel="sidebar"` wrapper (Section 5), and add a manual check.

Confirmed blocker/major remain (2, 3, 4, 7, 8, 9), so round 3 runs.

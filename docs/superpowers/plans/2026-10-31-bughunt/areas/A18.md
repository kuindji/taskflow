## Rounds

### Round 1 (2026-11-01): 4 findings, 4 confirmed

- R1-1 confirmed: Files > New File with a name already taken (e.g.
  `config.json`) sent `FILE_WRITE` with empty content, truncating the
  existing file to zero bytes, and the dialog closed as if it had worked.
  New `FILE_CREATE` message writes with `wx` and refuses a taken name with
  the same error New Folder and Rename give; an older backend without it
  refuses the unknown message instead of overwriting. 0454ff5a
- R1-2 confirmed: the editor's save cleared the dirty flag after the write
  answered even when more text had been typed meanwhile (an SSH primary makes
  the window wide). Switching tabs then disposed the "clean" model and the
  reload showed the older disk text, losing the later edits. Save now keeps
  the buffer dirty unless the model's version is the one it wrote. 0454ff5a
- R1-3 confirmed: refreshing a directory (any watch event for a file in it,
  e.g. an agent editing `README.md`) replaced its children with the backend's
  one-level listing, so an expanded subdirectory showed as open but empty
  until collapsed and reopened. A refresh now keeps the loaded children of
  directories that are still listed. 0454ff5a
- R1-4 confirmed: search results stay shown after moving to another
  machine's workspace (replace already acts on the results' machine), but
  clicking one opened the same path on the new workspace's machine at the old
  match line, or failed. A result now opens only while the workspace is on
  the machine it was found on. 0454ff5a

### Round 2 (2026-11-01): 4 findings, 3 confirmed, 1 owner

- R2-1 confirmed: Replace and Replace All sent the query and options as the
  inputs read by then, not the ones the shown results were found with.
  Clearing the search input (no new search runs below three characters)
  left the old results and Replace All enabled, and Replace All then sent
  `query: ""`, which rg matches at every position, rewriting every text file
  in the root (`foo` became `XfXoXoX`). A shortened query or a flipped
  regex toggle replaced something other than what was shown. The store now
  keeps the query and options with the results and replaces with those.
  b31e1316
- R2-2 owner: an open, clean editor is not refreshed when an agent changes the
  file on disk, and a save writes the whole buffer with no check that disk
  still holds what was loaded, so typing into the stale buffer and saving
  drops the agent's change. Needs a product call (see the index).
- R2-3 confirmed: with the same file open in both split panes (one Monaco
  model), switching the left pane to another file disposed the shared model
  once it was clean, leaving the right editor blank and unable to save. Also,
  the second pane's load (a `setValue` on the shared model) marked the first
  pane unsaved. The model is now disposed only when no other editor shows it,
  and a flush (reload) no longer counts as an edit. b31e1316
- R2-4 confirmed: replacing a match with empty text dropped the adjacent
  match on the same line (`foofoo`, first `foo` replaced by nothing) from the
  results: the later match was shifted onto the replaced match's column and
  then removed by those coordinates. The replaced match is now removed
  before the shift. b31e1316

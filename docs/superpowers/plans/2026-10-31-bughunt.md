# Bughunt cycle (2026-10-31)

takes the first uncleared area, has Astra (`gpt-6-astra` via Codex) hunt it
for real, verified bugs (not hypothetical edge cases), verifies and fixes
them, commits and pushes, and chains on. The same area is hunted again until
a round comes back clean, then the next area starts.

All work happens on `main` in this clone.

## Waiting for the owner

Findings that need a product decision. Each line names the area and finding
id.

- A01 R1-2: changing the data folder (Settings) leaves `flows/`, `flow-runs/`,
  `schedules.json` and `notifications.json` in the old folder. FlowStore,
  ScheduleStore, NotificationStore (and ThemeService) keep the paths they were
  built with, so after a restart they read the new, empty folder. Fix needs
  either live re-pointing of those stores (and the scheduler) or moving them
  plus a forced backend restart.
- A01 R2-1 (side note, root cause in A06): the POSIX `taskflow-cli task create`
  has no `--parent` and, in task context, creates a top-level task, while the
  Windows binary creates a subtask of the current task. The task-commands doc
  mentions neither. Pick one behaviour and document it.
- A05 R3-2: "Run now" on a disabled schedule now fails with "Schedule is
  disabled" (it used to do nothing and report success). Alternative: run it
  once and leave it disabled. (The UI now shows the error: A16 R1-3.)
- A08 R5-3: Terminal.app import (auto-detect and From File `.terminal`)
  never imports a real profile, because the colors are NSKeyedArchiver
  `<data>` blobs the parser does not decode. Either add a binary-plist +
  NSColor decoder or drop `.terminal` from the import sources.
- A10 R1-2: a saved discovered backend whose address changes (DHCP) keeps
  dialing the old address, and the uid match hides the beacon at the new one
  from the menu. Re-pointing the record from the beacon needs a decision on
  trust: the uid is broadcast in cleartext, so any LAN peer can repeat it.
  Workaround today: remove the machine and attach it again.
- A10 R2-2: when instance A's remembered port is taken by another Taskflow
  instance B on the same remote host, the anonymous readiness probe accepts B,
  A's token is rejected, and the record stays pointed at B until it is removed
  and re-added. A fix needs the probe to check identity (uid in the anonymous
  `/` response, or probing with the record's token while telling a stale token
  apart from a wrong backend), which changes the backend protocol.
- A13 R3-3: terminal file links (and drop paths) are POSIX-only: absolute
  paths must start with `/`, containment checks `cwd + "/"`, and
  `normalizePath` prefixes `/`, so a Windows session in `C:\repo` gets no
  links at all, relative or absolute, and Windows tools' `src\app.ts` output
  is not matched. Decide whether Windows terminal links are supported; if so
  the link provider needs drive letters and both separators.
- A15 R4-1: selecting an archived task in the sidebar does not open its
  workspace (keyboard selection shows the project, a click shows nothing).
  The workspace resolves only live tasks; archiving stops the task's sessions
  and task updates reject archived records. Decide whether an archived task
  opens a read-only view, a full workspace, or nothing (then make click and
  keyboard agree and skip selection).
- A16 R3-2: "Default"/"Model default" choices in Run with options, saved
  actions and schedules are sent as omitted fields, and the backend fills
  omitted fields from the machine defaults. So with Settings > Codex
  reasoning at `xhigh`, picking "Model default (high)" for a run still
  launches with `xhigh` (likewise Claude effort and model "Default"). Launch
  options have no value for "the CLI's own default". Decide whether "Default"
  there means the machine default (relabel) or the CLI default (add a
  sentinel to the shared launch-option types, CLI and TUI validation).
- A18 R2-2: the Monaco editor never notices disk changes. A clean buffer
  stays stale when an agent edits the file, and Save writes the whole buffer
  without checking that disk still holds what was loaded, so saving after
  typing into a stale buffer silently drops the agent's change. Options:
  reload clean buffers on `FILE_CHANGED` for their path (the workspace watch
  already delivers these), and for dirty buffers either warn on change or
  refuse a save whose disk text no longer matches the loaded text (needs an
  expected-content/mtime field on `FILE_WRITE`). Same gap (A20 R2-1): a
  markdown preview checkbox click reads the file then writes the toggled
  text, so an agent edit landing between the read and the write is lost.
- A20 R4-1: a markdown preview (and any other consumer of `FILE_CHANGED`)
  only refreshes while the file explorer holds a `FILE_WATCH` on a containing
  folder; the explorer is closed by default and closes when Search or Wiki
  opens. Wiki pages now reload from the wiki index, but other previews stay
  stale until reopened. A fix needs panes to hold their own watches, and the
  backend keeps one owner per client and path (a Set, not a count), so the
  explorer's unwatch would drop a pane's watch of the same folder. Decide
  whether watches become reference counted per client, or previews watch
  through another channel.

## Owner decisions (2026-11-02)

- A01 R1-2 → **A**: move every data-folder item (add `flows/`, `flow-runs/`,
  `schedules.json`, `notifications.json`), then restart the backend instead of
  re-pointing stores live. Refuse the change while sessions or flow runs are
  active. Electron's `backend-manager` has `startBackend` but no respawn; work
  out whether to respawn the backend or ask for an app relaunch. Implemented
  (cd0841d6, b3d6dd75).
- A01 R2-1 → **A**: `task create` makes a top-level task by default in both
  CLIs; `--subtask` (child of the current task) and `--parent <id>` create a
  subtask. Add both to the POSIX script and the TS binary, document them in
  the task-commands doc. Implemented (15a4c104, ce77eadc).
- A05 R3-2 → **A**: "Run now" on a disabled schedule runs it once and leaves
  it disabled (no re-arm, no `nextRunAt` change); running/offline checks stay.
  Implemented (1d642fad).
- A08 R5-3 → **B**: drop Terminal.app from theme import (auto-detect and the
  `.terminal` From File extension); delete its parser. Implemented (1d642fad).
- A10 R1-2 → **A**: when a beacon with a saved record's uid arrives from a new
  address, probe the new address over ssh with `HostKeyAlias=<old alias>`
  (StrictHostKeyChecking=yes). Key matches → update the record's host, copy
  the known_hosts line to the new alias, reconnect silently. Mismatch or no
  answer → leave the record, show the beacon as a separate entry (normal trust
  dialog). No backend protocol change.
- A10 R2-2 → **A**: anonymous `GET /` answers `Taskflow backend <instanceId>
  <backendUid>`; the readiness probe requires a match (uid when the record has
  one, else instanceId) and moves to the next candidate port on mismatch. A
  bare "Taskflow backend" (older backend) is still accepted.
- A13 R3-3 → **A**: support Windows paths in terminal links and drop paths
  (drive letters, both separators, case-insensitive containment), keyed to
  the session's backend OS, not the UI's OS.
- A15 R4-1 → **A**: archived tasks open a read-only view in the UI, matching
  the TUI's archived task detail (title, description, notes, attributes,
  archive date, Unarchive button; no sessions, no editing). Click and keyboard
  behave the same. Implemented (901451c0, 277d6d61).
- Found while deciding A15 R4-1: the backend purged archived tasks older than
  30 days on every startup (`TaskStore.cleanExpiredArchives`, records +
  session history + task log, never their worktrees). Owner: archives must
  never be purged. **Done 2026-11-02 (uncommitted)**: method, startup call,
  `ARCHIVE_EXPIRY_DAYS`, its test and the TUI "purged after 30 days" text
  removed.
- A16 R3-2 → **A**: "Default" in launch options (Run with options, saved
  actions, schedules; UI and TUI) means the value set in Settings for that
  agent (default model, effort/reasoning, permission mode, ...), applied when
  no other value is given. Labels must say that (e.g. "Default (xhigh, from
  Settings)"), not "Model default (high)". No CLI-default sentinel.
  Implemented (f21c781d, 6efa2ec0, 686129b6, 1198926f).
- Owner, 2026-11-02: remove the UI's "Run agent with task description" run-menu
  section (never used). **Done (uncommitted)**: section, its "with options"
  entries and the `onRunTab`/`showAgentOptions` plumbing removed from the run
  menu, task card, workspace dropdown and tab bar. Kept: "Run with options" via
  Shift+click on a favorite agent button (new blank session), and
  `taskflow-cli agent run --task <id>` (falls back to the task description).
- A18 R2-2 / A20 R2-1 → **A**: clean Monaco buffers reload on `FILE_CHANGED`;
  dirty ones show "Changed on disk — Reload / Keep mine". `FILE_WRITE` gets an
  optional expected hash/mtime; the backend refuses a mismatched write and the
  editor offers Reload or Overwrite. The markdown checkbox toggle sends the
  hash it read and retries once on conflict. Auto-reload depends on A20 R4-1.
- A20 R4-1 → **A**: reference-count watches in the UI `file-store`
  (`retainWatch`/`releaseWatch`; `FILE_WATCH` on 0→1, `FILE_UNWATCH` on 1→0,
  re-send live paths on reconnect). Explorer, editor tabs and markdown
  previews all go through it and watch the workspace root. Backend and
  protocol unchanged.

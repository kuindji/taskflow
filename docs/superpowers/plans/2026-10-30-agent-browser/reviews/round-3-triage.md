# Round 3 triage

Source: `round-3.md` (gpt-6.1-sol, read-only, against 0286d1f4). Chromium 130 (`render_frame_devtools_agent_host.cc`, `tracing_handler.cc`, `service_worker_handler.cc`) and Electron v33.4.11 (`guest-window-manager.ts`, `electron_api_web_contents.cc`) were fetched and checked. The type claims were re-probed with `bunx tsc` against `electron/node_modules/electron/electron.d.ts`.

Part A (round-2 fixes): agreed. The two "not fully" rows are findings 1 and 5.

1. **confirmed, blocker.** `render_frame_devtools_agent_host.cc:376-379` adds `ServiceWorkerHandler` (trusted client, so `allow_inspect_worker`) and, for the main frame, `TracingHandler` to page sessions. `tracing_handler.cc:826-840` adds the browser and GPU pids to the page's process filter. `service_worker_handler.cc:159-164,250-261` runs on the whole storage partition's SW context, so `stopAllWorkers` stops other tasks' workers. Rule 6's "everything else forwards" is a denylist in disguise; `Memory`, `BackgroundService`, `PWA` and others have the same shape. Fix: rule 6 becomes a session-level domain allowlist (default deny), with the boundary stated in the spec: effects inside the shared `persist:browser` partition are accepted (non-goal: per-task login isolation); effects on the browser or GPU process, the app's session, or other tasks' live targets are not. Puppeteer's `page.tracing` is refused as a result; recorded as a limitation.
2. **confirmed, major.** `guest-window-manager.ts:20-23,50-60` keeps one process-wide `frameNamesToWindow` map and calls `existingWebContents.loadURL(url)` before `createWindow`, with no opener check. Names are registered for guest popups (`:121-125`). A page in A's family can navigate B's named popup. Fix: `TabHost` tracks popup frame names per family root; `setWindowOpenHandler` denies a name owned by another family and allows reuse inside a family. Tests in Section 5, an integration case in Section 8.
3. **confirmed, major.** `TabHost.show` awaits `ensure` and `hide` is a no-op on an unloaded tab, so hide-during-creation loses; `freeze` hides after an async capture, so a newer `show` loses. Fix: per-tab visibility generation in `TabHost`; `show`, `hide`, `freeze`, `detachAll` and `close` bump it, and an awaited step applies its visibility only if its generation is still current. A creation that finishes after `close` destroys the view. `freeze` of a tab with no view resolves to `""`.
4. **confirmed, major.** Section 5 swallows a failed `closed` post; Section 2's heartbeat only marks absent tabs unloaded and never fires `subscribeTabGone`, so the UI tab, the saved root and the agent's browser socket all survive. Absence can't mean closed (lazy tabs). Fix: the backend link keeps an event that failed without an HTTP response at the head of the queue and retries it each tick before anything behind it; any HTTP response drops it. Strict order holds, and no event can block the queue forever while the backend answers.
5. **confirmed, minor.** Probe reproduced TS2740 (`options.webContents` narrows to `{}`) and TS2769 (`wc.on("close")`). `CloseContents` (`electron_api_web_contents.cc:1244-1254`) emits `close` and then calls `Destroy()`, so `destroyed` covers `window.close()`. Fix: an `isWebContents(value: unknown): value is WebContents` predicate (`webContents.fromId(value.id) === value`; probed, compiles) and `destroyed` for closure.

Outcome: one blocker and three majors confirmed, so round 4 runs. It is the last allowed round.

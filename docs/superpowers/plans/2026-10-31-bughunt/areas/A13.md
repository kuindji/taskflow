## Rounds

### Round 1 (2026-11-01): 2 findings, 2 confirmed

- R1-1 confirmed: switching to another task or project unmounts the
  workspace's terminals; 100 ms later TerminalPane deleted the session's input
  editor state because its xterm had left the cache, so an unsent prompt in
  the markdown input editor was gone on return although the session lived on.
  The draft is now dropped only once no tab shows the session
  (`releaseInputDraft`). 49a7ee44
- R1-2 confirmed: a file dropped onto a terminal was made relative to the
  active workspace's directory, not the session's own cwd. After moving a
  session from task A to task B, dragging B's `src/app.ts` from the explorer
  typed `src/app.ts`, which the session (still in A's worktree) reads as A's
  file. Drops now use the session's cwd, as clicked links already did
  (`droppedPath`). 49a7ee44

### Round 2 (2026-11-01): 3 findings, 3 confirmed

- R2-1 confirmed: closing a session tab whose machine was attached but
  unreachable (remote connection dropped, primary still up) removed the tab
  in a `finally` although no close reached the backend, so the session ran on
  without a tab until the next resync. The tab now stays unless the machine
  is detached (`closeTab`). 649f882a
- R2-2 confirmed: Send / Insert in the prompt editor cleared and closed it
  even when the input was dropped for lack of an open socket, losing the
  draft. `sendInput` now reports delivery and the editor keeps an undelivered
  draft. 649f882a
- R2-3 confirmed: a bare filename with a location (`app.ts:42:3`) linked only
  `app.ts`, so clicking opened the file at the top. The bare-name pattern now
  takes the `:line:col` suffix and stats the file without it. 649f882a

### Round 3 (2026-11-01): 3 findings, 2 confirmed, 1 owner

- R3-1 confirmed: with the workspace split, returning to it (Cmd+Shift+Arrow
  and releasing Shift, or a click from the sidebar) focused both panes'
  visible terminals in turn, so the right one won and typing went to its
  session while the left pane stayed marked active. A terminal now takes
  focus only in the active split pane (`paneFocused`). 7ba9b62e
- R3-2 confirmed: a terminal created in the master workspace (always aimed at
  a pane) held off the master-list broadcast and no master refetch followed,
  so its tab had no cwd and file links in it stayed dead until another master
  session changed. The create now refetches the master list, as resume did
  (`refetchRecords` `master`). 7ba9b62e
- R3-3 owner: terminal file links and drops assume POSIX paths (absolute
  regex, `/` containment, `normalizePath`), so a session in `C:\repo` on
  Windows gets no links. Windows support needs a path design; see the index.

### Round 4 (2026-11-01): 2 findings, 2 confirmed

- R4-1 confirmed: a terminal resized while its machine's connection was down
  (SSH tunnel dropped, PTY still running) sent a resize that was dropped, but
  TerminalPane recorded the new size as sent, and reconnect only refreshed
  output, so the PTY kept the old size and full-screen programs drew for the
  wrong dimensions until the next real resize or tab switch. Backend ready now
  resends a visible terminal's size (`subscribeTerminalRecovery` `resize`).
  e251f513
- R4-2 confirmed: flow runs for the open workspace were fetched only when the
  owner or machine changed, so a run that finished while the connection was
  down stayed "running" after reconnect: FlowPanel kept its running controls
  and the Run menu hid Flows. `useSessionSync` now refetches the owner's runs
  on backend ready. e251f513

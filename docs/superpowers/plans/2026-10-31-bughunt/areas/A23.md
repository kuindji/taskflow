## Rounds

### Round 1 (2026-11-01): 5 findings, 5 confirmed

- R1-1 confirmed: any task update (an agent's `taskflow-cli log info`) closed
  the task detail's open title/attribute editor and dropped the draft, so the
  next typed keys ran as commands (`d` deleted the selected attribute). Only
  a submitted edit's update closes the editor now; selection follows the
  attribute id. Commit: 8c48cfb2.
- R1-2 confirmed: an unrelated Settings refresh cleared the unsaved choice,
  so Enter saved the old value. The draft now survives refreshes until a
  save or the setting disappears. Commit: 8c48cfb2.
- R1-3 confirmed: flow library, schedules, notifications and settings moved
  the selection below the visible rows without scrolling, so Enter acted on
  an unseen row. A shared `followSelection` scrolls the selected row into
  view after layout. Commit: 8c48cfb2.
- R1-4 confirmed: the commit dialog took a typed `G` as Generate, so a
  message could not contain `G` and generation replaced the draft. Generate
  is Ctrl+G now. Commit: 8c48cfb2.
- R1-5 confirmed: a flow-library row click bypassed the pending guard, so a
  double click launched a standalone action twice. Commit: 8c48cfb2.

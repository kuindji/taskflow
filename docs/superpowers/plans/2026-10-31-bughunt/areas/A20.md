## Already handled

- External links in the preview open only through the Electron bridge
  (`window.taskflow.openExternalUrl`); the UI ships only inside Electron, so
  a "regular browser" has no shipped path to it.

  between the read and the write (R2-1): same missing FILE_WRITE
  precondition as owner item A18 R2-2; not a bug to raise per caller.

## Rounds

### Round 1 (2026-11-01): 2 findings, 1 confirmed

- R1-1 confirmed: react-markdown's default `urlTransform` read the drive
  letter of `C:/wiki/other.md` as an unknown scheme and blanked the href, so
  every wiki link under a Windows wiki root (and every explicit drive-letter
  link or image) rendered dead. The preview now uses `markdownUrlTransform`,
  which keeps drive-letter paths and defers to the default otherwise. d7b9ad04
- R1-2 rejected: external links do nothing without the Electron bridge; only
  reachable in a plain browser, which is not a shipped surface.

### Round 2 (2026-11-01): 3 findings, 2 confirmed

- R2-1 owner: a preview checkbox click reads the file, then writes the whole
  toggled text; an agent edit landing between the two is overwritten. Same
  root as A18 R2-2 (FILE_WRITE has no expected-content precondition); folded
  into that owner item.
- R2-2 confirmed: a legacy (non-hosted, e.g. remote workspace) browser tab
  hidden by `<Activity>` before its first `dom-ready` missed the event, so
  `webviewReady` stayed false and Reload/Back did nothing after it was shown
  again. The listener effect now probes the webview on (re)attach and marks
  it ready when the guest answers. 20177413
- R2-3 confirmed: wiki-link hrefs were raw filesystem paths, so a `#` in the
  wiki root ("C# notes") was read as the fragment and a `%` was decoded;
  clicking any wiki link opened the wrong path. `remarkWikiLink` now escapes
  `%` and `#` in the path. 357ffebb

### Round 3 (2026-11-01): 2 findings, 2 confirmed

- R3-1 confirmed: the wiki store never re-read an index after its machine
  reconnected. The backend watches a wiki only once asked for its index, so
  after a backend restart the panel, rail and wiki links stayed frozen on the
  old pages (pushes missed while the socket was down were lost too) until the
  panel was reopened. The store now re-reads every root it holds for a machine
  (failed ones included) on `onBackendReady`. 61dcca84
- R3-2 confirmed: a markdown preview's Edit button in Master fell through to
  Monaco instead of the configured CLI editor, because the owner came from the
  active workspace's scope, which had no Master branch. It now uses
  `workspaceOwner(workspaceKey)`, as `openFileInApp` does. 0b8ca67f

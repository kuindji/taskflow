# Bughunt cycle (2026-10-31)

Owner, 2026-10-31: split the app into areas; a chain of Taskflow sessions
takes the first uncleared area, has Astra (`gpt-6-astra` via Codex) hunt it
for real, verified bugs (not hypothetical edge cases), verifies and fixes
them, commits and pushes, and chains on. The same area is hunted again until
a round comes back clean, then the next area starts.

All work happens on `main` in this clone.

## Waiting for the owner

Findings that need a product decision. Each line names the area and finding
id.

- A01 R1-2: changing the data folder (Settings) leaves `flows/`, `flow-runs/`,
  `schedules.json` and `notifications.json` in the old folder. FlowStore,
  ScheduleStore, NotificationStore (and ThemeService) keep the paths they were
  built with, so after a restart they read the new, empty folder. Fix needs
  either live re-pointing of those stores (and the scheduler) or moving them
  plus a forced backend restart.
- A01 R2-1 (side note, root cause in A06): the POSIX `taskflow-cli task create`
  has no `--parent` and, in task context, creates a top-level task, while the
  Windows binary creates a subtask of the current task. The task-commands doc
  mentions neither. Pick one behaviour and document it.
- A05 R3-2: "Run now" on a disabled schedule now fails with "Schedule is
  disabled" (it used to do nothing and report success). Alternative: run it
  once and leave it disabled. (The UI now shows the error: A16 R1-3.)
- A08 R5-3: Terminal.app import (auto-detect and From File `.terminal`)
  never imports a real profile, because the colors are NSKeyedArchiver
  `<data>` blobs the parser does not decode. Either add a binary-plist +
  NSColor decoder or drop `.terminal` from the import sources.
- A10 R1-2: a saved discovered backend whose address changes (DHCP) keeps
  dialing the old address, and the uid match hides the beacon at the new one
  from the menu. Re-pointing the record from the beacon needs a decision on
  trust: the uid is broadcast in cleartext, so any LAN peer can repeat it.
  Workaround today: remove the machine and attach it again.
- A10 R2-2: when instance A's remembered port is taken by another Taskflow
  instance B on the same remote host, the anonymous readiness probe accepts B,
  A's token is rejected, and the record stays pointed at B until it is removed
  and re-added. A fix needs the probe to check identity (uid in the anonymous
  `/` response, or probing with the record's token while telling a stale token
  apart from a wrong backend), which changes the backend protocol.
- A13 R3-3: terminal file links (and drop paths) are POSIX-only: absolute
  paths must start with `/`, containment checks `cwd + "/"`, and
  `normalizePath` prefixes `/`, so a Windows session in `C:\repo` gets no
  links at all, relative or absolute, and Windows tools' `src\app.ts` output
  is not matched. Decide whether Windows terminal links are supported; if so
  the link provider needs drive letters and both separators.
- A15 R4-1: selecting an archived task in the sidebar does not open its
  workspace (keyboard selection shows the project, a click shows nothing).
  The workspace resolves only live tasks; archiving stops the task's sessions
  and task updates reject archived records. Decide whether an archived task
  opens a read-only view, a full workspace, or nothing (then make click and
  keyboard agree and skip selection).
- A16 R3-2: "Default"/"Model default" choices in Run with options, saved
  actions and schedules are sent as omitted fields, and the backend fills
  omitted fields from the machine defaults. So with Settings > Codex
  reasoning at `xhigh`, picking "Model default (high)" for a run still
  launches with `xhigh` (likewise Claude effort and model "Default"). Launch
  options have no value for "the CLI's own default". Decide whether "Default"
  there means the machine default (relabel) or the CLI default (add a
  sentinel to the shared launch-option types, CLI and TUI validation).
- A18 R2-2: the Monaco editor never notices disk changes. A clean buffer
  stays stale when an agent edits the file, and Save writes the whole buffer
  without checking that disk still holds what was loaded, so saving after
  typing into a stale buffer silently drops the agent's change. Options:
  reload clean buffers on `FILE_CHANGED` for their path (the workspace watch
  already delivers these), and for dirty buffers either warn on change or
  refuse a save whose disk text no longer matches the loaded text (needs an
  expected-content/mtime field on `FILE_WRITE`). Same gap (A20 R2-1): a
  markdown preview checkbox click reads the file then writes the toggled
  text, so an agent edit landing between the read and the write is lost.
